# E1 pilot: baselines on five tasks and the first LLM runs

Date: 2026-11-11. Status: **pilot**. The baselines are five seeds each. Every LLM cell is a single run with one model, so nothing below about the LLM arms is a result to cite; it decides what to run next.

All numbers are regenerated by the commands in `REPRODUCE.md`. Raw files: `experiments/e1_surrogate_head/results/` (baselines, trained heads as text) and `experiments/e1_surrogate_head/runs/<id>/` (prompt, raw reply, model self-report, meta, score).

## 1. Tasks

| Task | Application | Inputs | Target | Train / test | Split |
|---|---|---|---|---|---|
| `loop_bulk_modulus` | BO surrogate in the generative loop | 50 PCA components of ORB-v3 embeddings | bulk modulus, GPa (eSEN oracle) | 500 / 65 to 92 | warm-start pool → structures one generator run proposed; 6 runs, of which seeds 0 to 4 use the first five |
| `loop_heat_capacity` | same | same | heat capacity at 300 K, J/g/K | 445 / 31 to 59 | same; 5 runs |
| `mpea_yield_strength` | alloy design | 24 atomic fractions | room-temperature yield strength, MPa | 200 / 522 | random |
| `ti_alloy_youngs_modulus` | alloy design | 15 atomic fractions | Young's modulus, GPa | 120 / 117 | random |
| `matbench_log_bulk_modulus` | composition screening | 10 PCA components of composition statistics | log10 K_VRH | 500 / 10,487 | random |

In the two loop tasks each run fitted its own PCA basis, so a seed selects one run and both train and test rows come from it (`tests/test_campaign.py::test_closed_loop_split_never_mixes_runs`).

Top-decile bias is the mean of (predicted − true) over the test rows whose true value is in the top tenth.

What the baselines show:

- The GP is the best of the three on every task.
- Every method underpredicts the top tenth on every task. Part of that is what any regression does to extreme values, so the number alone does not prove a fixable fault.
- The GP's 95% interval covers 79% and 85% of the loop tasks' test rows, where the test rows come from a generator and not from the training distribution. On the three random-split tasks coverage is 89 to 93%.
- The MLP head on `matbench_log_bulk_modulus` is weak (R² 0.23 against ridge 0.43): the training recipe underfits there, and that head is not yet a fair gradient baseline.

## 3. Arm C: edit a trained head to stop underpredicting high values

The model saw the head's weights and its out-of-fold errors by decile of the true value. One run per row.

| Run | Weights changed | What the edit was | R² before → after | ρ before → after | Top-decile bias before → after | Affine recalibration: R², bias |
|---|---|---|---|---|---|---|
| `loop_bulk_modulus`, seed 0 | 33 of 2,721 (output layer) | predictions stretched ×1.15 about 125 GPa | 0.780 → 0.777 | 0.865 → 0.865 | −30.5 → −21.8 GPa | 0.777, −30.4 |
| `ti_alloy_youngs_modulus`, seed 0 | 33 of 1,601 (output layer) | stretched ×1.15 about 76 GPa | 0.484 → 0.407 | 0.690 → 0.690 | −15.4 → −10.1 GPa | 0.520, −23.3 |
| `loop_bulk_modulus`, seed 0, **weights shuffled** | 33 of 2,721 (output layer) | stretched ×1.18 about the training mean | not meaningful | not meaningful | not meaningful | |

Reading:

- The model made the same kind of edit on the shuffled network as on the real one, and reported that it was "derived only from the decile table, not from tracing the weights". In this arm, with this prompt, there is no evidence that the hidden weights were read at all. This agrees with the critiques in arXiv 2611.08070 and 2611.09559.
- The edit is a rescaling of the output. It cannot change the ranking, so it cannot change which candidates a ranking-based acquisition picks.
- It did reduce the top-decile bias in both real runs, at a cost in R² on the titanium task. Least-squares affine recalibration on the same out-of-fold predictions did not reduce it, because a least-squares fit of true on predicted has slope near one even when the decile table looks compressed. A fair cheap baseline for this arm is therefore a stretch fitted to the decile table, which is what the model did by hand; that baseline is not yet implemented.

## 4. Arm E: write a network from materials knowledge, no training data

The model saw only the names of the inputs and a description of the target. One reply per task; each reply scored over five data seeds.

| Task | Weights written | Alone: R² | Alone: ρ | Alone: RMSE |
|---|---|---|---|---|
| `ti_alloy_youngs_modulus` | 273 (5 of 16 hidden units used) | 0.01 ± 0.14 | 0.54 ± 0.05 | 21.7 ± 2.2 GPa |
| `mpea_yield_strength` | 417 (7 of 16 hidden units used) | 0.20 ± 0.02 | 0.63 ± 0.01 | 516 ± 11 MPa |

|---|---|---|---|---|---|
| `ti_alloy_youngs_modulus` | 10 | 0.06 ± 0.25 | −1.43 ± 2.97 | 0.47 ± 0.18 | 0.57 ± 0.07 |
| | 20 | 0.23 ± 0.23 | 0.26 ± 0.19 | 0.59 ± 0.13 | 0.62 ± 0.13 |
| | 50 | 0.40 ± 0.16 | 0.41 ± 0.19 | 0.69 ± 0.09 | 0.67 ± 0.14 |
| | 120 | 0.59 ± 0.07 | 0.61 ± 0.06 | 0.75 ± 0.08 | 0.73 ± 0.07 |
| `mpea_yield_strength` | 10 | 0.01 ± 0.12 | 0.02 ± 0.26 | 0.48 ± 0.09 | 0.59 ± 0.04 |
| | 20 | −0.06 ± 0.23 | 0.00 ± 0.36 | 0.42 ± 0.16 | 0.59 ± 0.05 |
| | 50 | 0.25 ± 0.12 | 0.27 ± 0.12 | 0.65 ± 0.03 | 0.66 ± 0.04 |
| | 200 | 0.55 ± 0.06 | 0.52 ± 0.05 | 0.78 ± 0.02 | 0.75 ± 0.01 |

Reading:

- With no data, the written networks rank alloys at ρ 0.54 and 0.63. For comparison a GP needs about 20 to 50 labels to reach the same ranking on these tasks.
- As a prior the written network raises ranking at 10 and 20 labels on both tasks and lowers its seed-to-seed spread. At 50 labels and more it makes no difference or slightly hurts.
- The R² at 10 labels on the titanium task collapses (−1.43 ± 2.97): the two-parameter rescaling of the prior is unstable on ten points. The slope needs shrinkage, or to be fixed at one.
- Five seeds, one reply, one model. The ranking gain at 10 to 20 labels is the only signal here worth a proper experiment.
- The untested alternative explanation is the cheapness one: a linear rule of mixtures written by a person from a handbook might do as well. That baseline is required before any claim.

## 5. How the model was called

Model: `claude-fable-5-2`, as a fresh Claude Code subagent on 2026-11-11. Each run got this wrapper, with the run folder substituted, and nothing else:

> You are the subject of an experiment that tests whether a language model can write [edit] neural-network weights by reasoning alone. The rules are strict and your tool use is audited afterwards: 1. Use the Read tool exactly once, on `<run>/prompt.txt`. 2. Do the task in that file purely by thinking. Do NOT run any code, do NOT use Bash, do NOT read, search or list any other file or directory, do NOT use the web. No calculator of any kind. 3. Use the Write tool exactly once to save your reply to `<run>/reply.txt` — the file must contain ONLY what the prompt's "Reply format" section asks for. 4. Then answer me with two or three sentences describing the approach you took. Total tool calls must be exactly 2.

The harness reported two tool calls for every run. The restriction was by instruction and checked by that count; it was not enforced by a sandbox. Token use is recorded per run as the harness's total for the subagent session (55,609 to 67,430), which includes its system prompt and reasoning; prompt and reply tokens were not counted separately. A model's replies are not deterministic: re-running a prompt gives a different reply, which is why the raw replies are stored.

## 6. What this changes in the plan

1. Arm C as prompted does not test weight reading. Replace it with faults that only the hidden weights reveal: a planted leak input, a dead or sign-flipped unit, a label shift above a threshold (the audit design of arXiv 2611.05341). Keep the shuffled control.
2. Add the decile-stretch baseline, and for arm E a hand-written rule-of-mixtures baseline and a shrunk prior slope.
3. Run arm E properly: at least five replies per task, a second model, and labels at 5, 10, 20, 50; then inside a BO loop on the same two tasks, where an early ranking gain should show as lower regret.
4. Fix the MLP recipe on `matbench_log_bulk_modulus` before using that head.
