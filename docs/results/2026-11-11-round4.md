# Round 4: generator filter, leak repair across models, BNN start and prior

Date: 2026-11-11. Commands are in each script's docstring; raw runs under `experiments/<e>/runs/`. Model ids are read from the harness transcripts (`experiments/runs_audit.json`; 150 runs, all passed the tool audit).

## 1. An LLM-written filter in front of the crystal generator

`experiments/e3_crystal_filter/filter_arm.py`; table `results/filter_arm/summary.md`. The generator is untouched. A 15 → 16 → 1 network, written with no data from named descriptors (volume per atom as generated, mean atomic mass, electronegativity, melting point, eleven element-group fractions), scores each sampled crystal; the top quarter would go to the oracle. Tested on the 128 base-model crystals scored on FASTER with the eSEN oracle (hit: bulk modulus above 150 GPa; 9% of samples).

| Scorer | Replies | ρ with oracle | Mean bulk modulus, all → kept quarter (best possible 147) | Hit share, all → kept | Oracle calls to half the hits (random order 60) |
|---|---|---|---|---|---|
| Opus 5.5 | 2 scored of 3 | 0.94 | 71.6 → 144 | 0.09 → 0.38 | 6 |
| Fable 5.2 | 3 | 0.88 | 71.6 → 143 | 0.09 → 0.38 | 7 |
| Sonnet 5.5 | 3 | 0.80 | 71.6 → 143 | 0.09 → 0.38 | 7 |
| Haiku 5.5 | 3 | 0.73 | 71.6 → 129 | 0.09 → 0.29 | 9 |
| rule: small volume per atom | | 0.82 | 71.6 → 133 | 0.09 → 0.38 | 10 |
| same network trained on 400 MP structures | | 0.29 | 71.6 → 51.2 | 0.09 → 0.00 | 60 |

The Opus row was scored before its third reply returned; rerun `filter_arm.py score` to include it.

- The written filter works: it doubles the mean bulk modulus of what reaches the oracle and is within 4 GPa of the best possible quarter.
- The gain over a one-line rule is modest (ρ 0.94 against 0.82; 144 against 133 GPa; 6 against 10 oracle calls).
- The network trained on 400 Materials Project structures does not transfer to generated crystals. The cause was not isolated; relaxed versus as-generated volumes is the obvious suspect.
- Heat capacity per gram: the Dulong-Petit rule (1 / mean atomic mass) ranks at ρ 1.00 on the crystals for which the oracle returned a value, and every written network matches it. There is nothing for a model to add.

## 3. The written network as a BNN's start, prior or prior mean

`experiments/e5_bnn_start/run_bnn.py`; `results/bnn_summary.md`. Networks: the Opus 5.5 and Fable 5.2 replies already collected (alloy write arm; bulk-modulus filter arm for Matbench). Six tasks (five alloy tasks, Matbench K_VRH with 10,973 crystals), 10 / 20 / 50 / 200 labels, five seeds. IBNN was dropped; HMC follows the study of BNN surrogates for BO by Li, Rudner and Wilson, re-implemented.

Mean over model × task cells (24 cells at 10 or 20 labels, 18 at 50 or 200):

| BNN | Arm | ρ, ≤ 20 labels | ρ, ≥ 50 labels | 95% coverage, ≤ 20 | Cells where it beats its baseline, ≤ 20 labels |
|---|---|---|---|---|---|
| GP (reference) | plain | 0.53 | 0.74 | 0.71 | |
| | written network as prior mean | **0.69** | 0.77 | 0.66 | 23 of 24 |
| MC dropout | random start | 0.54 | 0.74 | 0.45 | |
| | starts at written weights | 0.54 | 0.68 | 0.88 | 12 of 24 |
| | starts there, anchored | 0.54 | 0.68 | 0.89 | 12 of 24 |
| | written network as prior mean | **0.65** | 0.75 | 0.39 | 22 of 24 |
| Deep ensemble | random starts | 0.50 | 0.70 | 0.60 | |
| | starts at written weights + noise | 0.57 | 0.71 | 0.71 | 19 of 24 |
| HMC | zero-centred prior | 0.45 | 0.67 | 0.94 | |
| | chain starts at written weights | 0.40 | 0.66 | 0.93 | 2 of 24 |
| | prior centred on written weights | 0.21 | 0.61 | 0.90 | 0 of 24 |

- **End point, yes.** As a prior mean in function space the written network helps every model it was tried on when labels are few: GP 0.53 → 0.69, MC dropout 0.54 → 0.65, in 23 and 22 of 24 cells.
- **Starting point, mostly no.** Starting MC dropout at the written weights does not improve ranking and costs 0.06 at 50 labels and more; it does widen the error bars toward nominal coverage (0.45 → 0.88). A deep ensemble started there gains a little (0.50 → 0.57, 19 of 24 cells). HMC gains nothing from starting there.
- **Weight-space prior, no.** Centring HMC's Gaussian prior on the written weights is the worst arm (ρ 0.21 at few labels). The written networks use three to seven hidden units with large weights; a unit-variance prior around them pins the rest of the network at zero and the chain cannot use the data.
- Calibration caveat: the prior-mean versions of the GP and MC dropout are overconfident at few labels (coverage 0.66 and 0.39); the slope and offset of the prior are fitted on the same few labels and that uncertainty is not propagated.
- HMC here uses a fixed noise level (0.3 in standardised units), one chain, 200 kept samples; the acceptance rate was logged per chain. It is a small implementation, not a tuned one.
- Not covered: the Pheasy phonon set (its file needs NumPy 2 with pymatgen), SGHMC and linearised Laplace.
