I sorted the error tokens into those the model emits only in wrong cells (zero occurrences in correct cells: merged no-space tokens such as '/K', '/J', ')+', '+(', '→', '℃', LaTeX '$\\', 'tl', 'é'), which I pushed down firmly, and the printed-side tokens that also never occur in correct cells (space-prefixed ' /', ' →', ' +', ' ±', ' °', ' K', Greek with a leading space, 'ν'), which I raised moderately so that clear visual evidence can still override them. Digits, '.', '(', ')' and the hyphen '-' have many correct occurrences, so I left them alone. I gave the en dash and minus sign only small boosts and the bare space token a moderate one, because the 83 hyphens in correct cells (mostly hyphen-printed negative numbers) must stay right. I left out the superscript and combining-mark byte tokens (⁻¹, ᵃ, H̄) as unsafe, so the roughly 45 unit-header cells with mol⁻¹ will stay wrong whatever else changes. I expect a modest net gain, mainly on dash cells, '< 27'-type cells, reaction equations and 'T / K' or 'T (°C)' headers, and I am about 55% confident it does not break any currently correct number cell on new papers.
